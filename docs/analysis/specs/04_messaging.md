# Messaging Spec

## Canonical Tables

- `messages`
- `message_reads`
- `message_pins`
- `message_attachments`

## Structural Rules

- `messages` belongs to exactly one `channels` record.
- Each `messages` row has exactly one sender stored by `sender_user_id`.
- `messages.parent_message_id` is optional and supports simple reply threading (one level deep in Phase 1).
- `message_reads` stores the latest read-checkpoint per user per channel, not per message; unread count is derived at query time.
- `message_pins` stores persisted pin/unpin events for quick-access and moderation history.
- `message_attachments` stores file metadata linked to one message; binary content lives in object storage.

## Table Definitions

### `messages`

Core communication record inside a channel.

| Column | Type | Constraints | Description |
|---|---|---|---|
| `id` | `bigint` | PK, auto-increment | Internal surrogate key. Sequential to support efficient range queries. |
| `uuid` | `uuid` | NOT NULL, unique | Public identifier exposed in API responses and websocket events. |
| `channel_id` | `bigint` | NOT NULL, FK → `channels.id` CASCADE, index | Owning channel. Cascades so all messages are removed when a channel is hard-deleted. |
| `sender_user_id` | `bigint` | NOT NULL, FK → `users.id` RESTRICT, index | The user who posted the message. |
| `parent_message_id` | `bigint` | nullable, FK → `messages.id` SET NULL, index | References the root message this is a reply to. Null for top-level messages. |
| `message_type` | `varchar(20)` | NOT NULL, default `'text'` | Content kind: `text` \| `system` \| `file` \| `call_event`. `system` messages are generated by the platform (member joined, channel renamed, etc.). |
| `content_text` | `text` | nullable | Markdown or plain-text body. Null for `file`-only or `system` messages. |
| `metadata_json` | `jsonb` | NOT NULL, default `'{}'` | Supplementary data: link preview, poll options, call duration, or system-event details. |
| `edited_at` | `timestamptz` | nullable | Set when the message body is edited. Null means never edited. |
| `edited_by` | `bigint` | nullable, FK → `users.id` SET NULL | The user who performed the last edit. Typically the sender; admins may also edit in some configurations. |
| `deleted_at` | `timestamptz` | nullable | Soft-delete marker. Non-null means the message body is hidden and replaced with a tombstone in the UI. |
| `deleted_by` | `bigint` | nullable, FK → `users.id` SET NULL | The user who deleted the message (sender or admin). |
| `created_at` | `timestamptz` | NOT NULL, auto-set | Message send timestamp. Used for chronological ordering. |

**Indexes:** unique on `uuid`, index on `channel_id`, index on `sender_user_id`, index on `parent_message_id`, composite index on `(channel_id, created_at)` for pagination

**`message_type` values:** `text` | `system` | `file` | `call_event`

**Derivation rules:**
- Edited: `edited_at IS NOT NULL`
- Deleted: `deleted_at IS NOT NULL`
- Is reply: `parent_message_id IS NOT NULL`

**`metadata_json` shape (examples):**
```json
// text message with link preview
{
  "link_preview": {
    "url": "https://example.com",
    "title": "Example",
    "image_url": "https://example.com/og.png"
  }
}

// system message
{
  "event": "member_joined",
  "subject_user_id": 42
}
```

### `message_reads`

Per-user, per-channel read checkpoint. Drives unread-count computation.

| Column | Type | Constraints | Description |
|---|---|---|---|
| `id` | `bigint` | PK, auto-increment | Surrogate key. |
| `channel_id` | `bigint` | NOT NULL, FK → `channels.id` CASCADE, index | The channel being tracked. |
| `user_id` | `bigint` | NOT NULL, FK → `users.id` CASCADE, index | The user whose read position is recorded. |
| `last_read_message_id` | `bigint` | NOT NULL, FK → `messages.id` RESTRICT | The highest `messages.id` the user has acknowledged reading. All messages with `id > last_read_message_id` are counted as unread. |
| `last_read_at` | `timestamptz` | NOT NULL | Wall-clock time of the last read acknowledgment. Used for TTL-based cleanup if needed. |
| `updated_at` | `timestamptz` | NOT NULL, auto-updated | Row last-modification timestamp. |

**Indexes:** composite unique on `(channel_id, user_id)`, index on `channel_id`, index on `user_id`

**Unread count query pattern:**
```sql
SELECT COUNT(*)
FROM messages
WHERE channel_id = :channel_id
  AND id > :last_read_message_id
  AND deleted_at IS NULL
```

**Note:** There is exactly one `message_reads` row per (user, channel) pair. The row is upserted on each read acknowledgment, not appended.

### `message_pins`

Persisted pin record. A pinned message is surfaced in the channel's pin list.

| Column | Type | Constraints | Description |
|---|---|---|---|
| `id` | `bigint` | PK, auto-increment | Surrogate key. |
| `channel_id` | `bigint` | NOT NULL, FK → `channels.id` CASCADE, index | The channel that owns this pin. Denormalized from `message.channel_id` to allow efficient pin-list queries without joining messages. |
| `message_id` | `bigint` | NOT NULL, FK → `messages.id` CASCADE, index | The pinned message. |
| `pinned_by` | `bigint` | NOT NULL, FK → `users.id` RESTRICT | The user (with pin permission) who pinned the message. |
| `unpinned_by` | `bigint` | nullable, FK → `users.id` SET NULL | Set when the message is unpinned. Null means currently pinned. |
| `pinned_at` | `timestamptz` | NOT NULL | When the message was pinned. |
| `unpinned_at` | `timestamptz` | nullable | When the message was unpinned. Null means currently pinned. |
| `created_at` | `timestamptz` | NOT NULL, auto-set | Row creation timestamp. |

**Indexes:** composite unique on `(channel_id, message_id)` for active pins, index on `channel_id`

**Active pin check:** `unpinned_at IS NULL`

**Note:** A message can be pinned, unpinned, and re-pinned. Each pin cycle may create a new row, or the existing row may be updated depending on the application's audit requirements.

### `message_attachments`

File metadata linked to one message. Binary content is stored externally in object storage.

| Column | Type | Constraints | Description |
|---|---|---|---|
| `id` | `bigint` | PK, auto-increment | Surrogate key. |
| `message_id` | `bigint` | NOT NULL, FK → `messages.id` CASCADE, index | Parent message. One message may have multiple attachments. |
| `file_name` | `varchar(500)` | NOT NULL | Original file name as uploaded by the user, e.g. `"Q3_report.pdf"`. |
| `mime_type` | `varchar(255)` | NOT NULL | IANA media type, e.g. `image/png`, `application/pdf`. Used to determine preview rendering in the UI. |
| `file_size` | `bigint` | NOT NULL | File size in bytes. Used for quota accounting and display. |
| `storage_path` | `varchar(1000)` | NOT NULL | Internal object-storage path relative to the configured bucket root, e.g. `tenants/42/messages/1234/report.pdf`. |
| `url` | `varchar(1000)` | NOT NULL | Publicly accessible (or pre-signed) download URL. May be regenerated if the storage backend URL changes. |
| `thumbnail_url` | `varchar(1000)` | nullable | URL of a reduced-resolution preview image. Null for non-visual file types (PDF, archive, etc.). |
| `created_at` | `timestamptz` | NOT NULL, auto-set | Row creation timestamp. |

**Indexes:** index on `message_id`

**Type inference:** `attachment_type` is intentionally omitted. The `mime_type` column carries this information; application code uses it for rendering decisions.

## Constraint Summary

| Rule | Details |
|---|---|
| Soft delete on messages | `deleted_at IS NOT NULL` hides the body; the row is preserved for thread continuity. |
| Reply depth | Phase 1 supports one level of threading. A reply's `parent_message_id` must point to a root message (`parent_message_id IS NULL`). |
| Single read checkpoint per user-channel | Composite unique on `(channel_id, user_id)` in `message_reads`. |
| Attachments are optional | Most messages have no attachment rows. |
| No redundant tenant/workspace keys | `messages`, `message_reads`, `message_pins`, and `message_attachments` do not carry `tenant_id`; tenant scope is derived through `channel_id → channels.tenant_id`. |

## Query-Oriented Guidance

- Unread count is derived from `message_reads` and channel activity at query time — not stored on each message.
- Boolean flags `is_edited` and `is_deleted` are unnecessary; use `edited_at IS NOT NULL` and `deleted_at IS NOT NULL`.
- Chronological pagination should use `(channel_id, id)` or `(channel_id, created_at)` composite indexes for consistent ordering.
- Pin list queries filter `message_pins` by `channel_id` and `unpinned_at IS NULL`.
